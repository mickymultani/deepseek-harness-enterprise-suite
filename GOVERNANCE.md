# Governance

## Principles

The project is community-driven, security-conscious, vendor-neutral, and transparent about capability maturity. Maintainers prioritize safe extension contracts and interoperability over the number of integrations.

## Roles

- Contributors propose and implement changes.
- Reviewers provide sustained technical or domain review.
- Maintainers merge changes, publish releases, manage security reports, and enforce project policy.

Maintainer status is earned through consistent, high-quality contributions and responsible review. Existing maintainers approve new maintainers by consensus.

## Decisions

Routine changes use pull-request review. Public API, security model, governance, licensing, or compatibility decisions require a design issue and maintainer consensus. When consensus is not possible, maintainers document the alternatives and decide based on user safety, compatibility, maintainability, and project scope.

## Releases

Maintainers publish releases from protected tags after CI, packaging, clean-install, and Harness profile integration checks pass. Security releases may use an expedited private process followed by coordinated disclosure.

## Independence

The project is not governed by DeepSeek AI or the vendors named in connector packages. Compatibility statements describe tested behavior and do not imply endorsement.
